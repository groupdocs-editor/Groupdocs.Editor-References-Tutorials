## Veelgestelde vragen

**Q:** *Kan ik form values Java lezen uit een PDF die ondertekend is?*  
**A:** Ja. Na het laden van de ondertekende PDF met GroupDocs.Editor kun je nog steeds de form‑field API aanroepen om waarden op te halen, op voorwaarde dat de handtekening de formuliergegevens niet versleutelt.

**Q:** *Hoe stel ik form value Java in voor een dropdown‑lijst?*  
**A:** `setValue` is een methode van een formulierveldobject die een nieuwe waarde aan het veld toewijst. Gebruik de `setValue`‑methode op het specifieke veldobject en geef de exacte optie‑tekst door die overeenkomt met een van de dropdown‑items.

**Q:** *Is er een manier om form fields Java in bulk te wissen?*  
**A:** Zeker. `FormFieldCollection` vertegenwoordigt de collectie van alle formuliervelden in een document. Iterate over de `FormFieldCollection` en roep `clear()` aan op elk veld (`clear()` verwijdert de huidige waarde van een formulierveld), of gebruik de `clearAll()`‑helper (`clearAll()` wist elk veld in één keer) indien beschikbaar in de versie die je gebruikt.

**Q:** *Ondersteunt GroupDocs.Editor het laden van een Word-document Java en het converteren naar een PDF met behouden formuliervelden?*  
**A:** Ja. Laad de DOCX met de editor, voer eventuele noodzakelijke veldaanpassingen uit, en sla vervolgens het document op als PDF – alle formulierinteractiviteit blijft behouden.

**Q:** *Wat moet ik doen als een formulierveld niet wordt herkend na het laden?*  
**A:** Voer de “fix invalid form fields” tutorial uit die hierboven is gelinkt; de API zal proberen ontbrekende velddefinities te repareren of opnieuw te creëren.
